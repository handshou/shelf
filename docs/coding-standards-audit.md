## Selected atomic fix: multipart media upload boundary

The original POST route cast form fields to File/string, called `directory.replace` without refining the value, rejected Response objects on provider failures, and logged/returned provider error details. Missing or file-valued directory fields could crash otherwise authorized uploads. Malformed multipart bodies and stream errors had no safe response contract.

- `src/lib/media-upload-route.ts`: parses real multipart input into a File plus normalized folder, keeping authorization before any body read. Missing/wrong-type fields and unreadable multipart bodies return JSON 400.
- `src/lib/cloudinary-upload.ts`: reuses the existing SDK through a narrow writable-stream seam. File-read failures, synchronous SDK failures, callback failures, stream errors, and malformed provider responses return `MediaUploadUnavailable` values instead of rejecting.
- `src/pages/api/cloudinary/[...media].ts:85`: composition wiring preserves the existing Tina authorization and configured-app check; POST no longer mutates/casts the Request or decodes an irrelevant pathname.
- Provider failures render JSON 502 with a safe `message` understood by the installed Tina media store. Diagnostics contain only tag/provider/operation. Successful responses retain provider fields and require Tina's public_id, secure_url, and original_filename fields.
- Existing upload semantics remain: one leading folder slash removed, root upload supported, use_filename enabled, auto resource type, overwrite disabled, and no retries.
- `tests/unit/media-upload.test.mjs`: 16 real multipart/writable-stream cases through the new route/adapter seams. Existing auth regressions remain; their provider fixture now contains the response fields required by Tina.
- `tests/media-upload.test.ts`: two public HTTP authorization regressions, each run in all three browser projects. Successful authorized uploads use a local writable substitute rather than mutating a real Cloudinary account.

No generic result framework, repository abstraction, configuration migration, new dependency, or unrelated UI change was introduced. The local tagged unions belong to their boundaries. The existing direct request-to-provider composition is contained at the upload seam; a broader application-service/authentication redesign is deferred rather than introducing a pass-through service with no additional policy.
